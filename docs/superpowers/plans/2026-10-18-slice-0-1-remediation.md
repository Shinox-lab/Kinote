# Slice 0/1 Remediation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Take the Slice 0 (Foundations) and Slice 1 (Live pages) code in this repo from "tests pass on a stubbed, in-memory, unauthenticated build" to the behaviour `docs/2026-10-18-living-wiki-standalone-design.md` specifies, on a real Postgres, with real authentication, a safe indexer and the missing Slice 1 surfaces.

**Architecture:** Five ordered steps. (1) Real identity (sessions, signed collab tokens, invitations) and one error model. (2) Real Postgres with a clean Drizzle migration chain, a leased job queue and S3 storage, in containers. (3) An indexer that cannot publish withdrawn or stale content and chunks real BlockNote blocks. (4) Hocuspocus 4, server-derived authorship, and a single permission gate. (5) The missing API routes and a rebuilt console. Shared domain code moves to `packages/core` first so api, worker and collab stop importing each other's source.

**Tech Stack:** TypeScript pnpm monorepo, Node 22, Fastify 5, Drizzle + `pg` (PGlite in tests), Zod, Hocuspocus 4, Yjs, BlockNote 0.49, pgvector 0.8 on Postgres 17, Vitest, Playwright, React 19, TanStack Router and Query, Tailwind 4, `@node-rs/argon2`, `@aws-sdk/client-s3`.

**Spec:** `docs/2026-10-18-living-wiki-standalone-design.md` (rule numbers below refer to its "Rules the system must keep"). Findings being fixed come from the review of the code as found; each task names what it fixes.

## Global Constraints

- Node 22 or later (Hocuspocus 4); Postgres 17 with pgvector 0.8 or later; embedding dimensions 4,000 or fewer (`halfvec` HNSW).
- `tenant_id` on every row; RLS enabled and forced on every table; the app role does not bypass RLS; `app.tenant_id` is set at the start of every transaction; every query still filters on `tenant_id`.
- Another tenant's ids, and spaces the actor cannot read, answer 404, never 403; a readable resource the role cannot change answers 403 `forbidden`; malformed ids answer 404.
- Agents hold `viewer` or `editor`, never `reviewer` or `admin`; an agent's change always needs a person's approval; the author of a snapshot cannot approve it unless the space has `allow_self_approval` (default false); agent contributions always need someone else.
- Permissions are applied inside the search query, before ranking; full-text uses the `simple` configuration; vector and full-text results merge with reciprocal rank fusion.
- Indexed text of a page is `# {title}\n\n{markdown}`; only chunks of indexed versions exist; indexing a version inserts its chunks and deletes the old version's chunks in one transaction.
- Rule 9: withdraw, archive and source deletes need no approval and leave the index in the same transaction.
- Every job is idempotent and keyed by what it acts on; failed jobs go to a dead-letter list.
- Contracts first: a route's Zod schema is written before its handler; business rules live in api and worker, the browser only displays the badge it is given.
- Defaults: `quiet_seconds` 120, `human_protection_seconds` 300, rejection note 1–300 characters, files 50 MB.
- The console maps every error code to a plain sentence; raw codes are never shown.
- Migrations are generated by Drizzle, never hand-edited; RLS SQL is generated then reviewed.
- Tests: Vitest with PGlite (pgvector) for services and RLS, an in-process Hocuspocus for collab, a deterministic fake embedding provider, Playwright with two browser contexts for co-editing. Every slice ends with a written live check against the real stack.

## Review Focus

Failure modes the spec implies that no existing test exercises, most likely first. Each has a test in the task named.

1. A valid session for one tenant used with another tenant's `x-tenant-id`, or with a forged role header, must never act (404 `tenant_not_found`; role comes from the database). → Task 1.3.
2. Typing that lands while a snapshot is being taken must not be marked as snapshotted. → Task 3.6.
3. Odd and large pages: a 900-word single paragraph, a table, nested list items, a 1,500-word section. Chunks never split a block, none is empty, ids are real. → Task 3.2.
4. The embedding provider failing mid-index: nothing half-written, the old version stays searchable, the page ends "Index failed" with a working Retry. → Tasks 3.3, 3.4.
5. Removing or demoting the last owner of a tenant must be refused (`last_owner`). → Task 5.1.
