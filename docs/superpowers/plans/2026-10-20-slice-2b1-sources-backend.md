# Slice 2b-1: Sources Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A tenant admin can create an upload-API source and tokens; a script can `PUT` and `DELETE` files by `external_id` with the right review, delete and revive behaviour; viewers read only the published version; and the 2a loose ends the console would expose are fixed. No console change.

**Architecture:** Three new tenant tables (`sources`, `source_items`, `source_tokens`) with RLS. A new route auth mode `'source'` resolves a bearer token (which carries its tenant id, so lookup stays inside RLS) to a `SourceActor`. Script routes reuse 2a's detection, storage and `insertFileVersion`; only authorship, placement and lookup differ. The trusted switch and the source-delete guard live in `extractVersion`/`indexVersion` in `packages/core`.

**Tech Stack:** Fastify 5, Drizzle + drizzle-kit, Zod contracts, PGlite tests, `pnpm test:pg` for the real-Postgres app-role checks.

**Spec:** `docs/superpowers/specs/2026-10-20-slice-2b-sources-and-console-design.md` (Part 1, "Carried over from 2a", edge cases 1–11, 17–20). Parent: `docs/superpowers/specs/2026-10-20-slice-2-files-design.md`.

## Global Constraints

- Contracts first; replies camelCase, requests snake_case; every reply through `parseReply`; every query tenant-filtered inside `withTenantTx`.
- Document lock first (`lockDocument`), then version rows. A source-delete and a `PUT` of the same id serialise on it.
- Token format `lws_{tenantId without dashes}.{secret}`, secret = 32 random bytes base64url; stored as `sha-256(token)` (`sha256Hex` from `@kinote/shared`); shown once; never logged, audited or returned after creation.
- Every authentication failure on a source route is the same `401 unauthenticated` with the same body.
- Plain error sentences only: new codes `not_removed` (409, "This file has not been removed at its source.") and `source_name_taken` (409, "A source with this name already exists in your organisation.").
- Migrations: `0012` generated by `pnpm db:generate`; `0013` custom, RLS from `node packages/db/scripts/gen-rls.mjs --tables sources,source_items,source_tokens` plus `REVOKE DELETE ON public.sources FROM kinote_app;`. Never hand-edit a generated file.
- Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Work stays on branch `slice-2-files`.
- Gates after every task: `pnpm typecheck` and the named tests; the whole suite (`pnpm vitest run`) must stay green.

## Review Focus

1. **A token valid for tenant A used with tenant B's id, ids, or paths** must be the same 401 as garbage, and must never touch B's rows (Task 3 test).
2. **`DELETE` racing extraction or indexing**: the in-flight job must not put the file back (Task 4 tests, core and API).
3. **`unchanged` after a person replaced or withdrew a synced-then-pinned file**: the next identical `PUT` must change nothing (Task 3).
4. **A viewer asking for a waiting, rejected or older version's bytes or text** by id: 404, never the bytes (Task 6).
5. **Double `PUT` / `PUT` + `DELETE` simultaneously**: one document, a consistent final state (Tasks 3–4).
