# Routing 3a — Placement retrieval (page cards and entity graph) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the retrieval layer the routing engine places facts with: a page card per indexed page and an entity graph
derived from indexed versions, both kept in step with index, withdraw and move, plus the access-filtered queries over
them.

**Architecture:** Two new worker jobs (`version.card`, `version.entities`) run after `version.index` succeeds. Each
follows `indexVersion`'s pattern: read in a short transaction, call the model and embedder with no transaction open,
then publish under the document lock after re-checking that the version is still the indexed one. A new
`PlacementModel` provider, built like the Ask provider (deterministic for tests, OpenAI-compatible otherwise), writes
summaries and extracts entities. Every derived row carries `space_id`. Withdraw, return-to-review and move update or
delete these rows in the same transaction as the chunks.

**Tech Stack:** TypeScript, Drizzle, Postgres 17 + pgvector (`halfvec(2560)`) + `pg_trgm`, PGlite for tests, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-26-routing-engine-design.md`. This is plan 1 of 3:
- **3a** (this plan): retrieval layer.
- **3b**: captures, the engine, apply, suggestions, undo and move, Needs a home, the R1 review change, the evaluation
  script.
- **3c**: the console — Capture page, receipts, "changes from this capture", review bundles.

## Global Constraints

- Every new table has `tenant_id uuid not null references tenants(id)` and RLS. The RLS migration is generated by
  `node packages/db/scripts/gen-rls.mjs --tables …` into a `drizzle-kit generate --custom` file and never hand-edited.
- Every query filters on `tenant_id` even with RLS on (main design, "Conventions for plans").
- Embeddings are `halfvec(2560)` from the configured `EmbeddingProvider`. A vector of any other length is a
  `NonRetryableError`, as in `indexVersion`.
- Cards and the graph are derived from **indexed versions only**. They carry `space_id`, follow moves in the same
  transaction, and are deleted with a withdrawal in the same transaction (R7).
- **The Inbox is skipped (R17):** no card, mentions or edges for documents in a `kind = 'inbox'` space.
- Files get no card, but they do get entities (they are candidates for graph hops, never edit targets).
- Entity kinds: `person`, `team`, `system`, `organisation`, `project`, `place`, `other`. Edge types: `owns`, `uses`,
  `part_of`, `depends_on`, `member_of`, `related_to`.
- Entity extraction is cached by `(tenant_id, model, content_hash)`; an unchanged chunk is never sent to the model twice.
- Model output is untrusted data. It is parsed with Zod; anything invalid is retried once, then fails with
  `router_unavailable` (503, retryable job).
- No transaction is held across a model or embedding call (`indexVersion` pattern; PGlite deadlocks otherwise).
- Graph lookups go at most two hops and filter mentions and edges by the actor's readable spaces **before** following
  them (R6, R7).

## Review Focus

1. **A page re-indexed while its card job is still running.** The old job must not overwrite the newer card. Pinned by
   Task 3's `skips when a newer version was indexed meanwhile`.
2. **A document moved into the Inbox, or into a space the actor can't read.** Its entities must stop being discoverable
   at once. Pinned by Task 5's `moving into the Inbox deletes the card, mentions and edges` and Task 7's
   `entity found only through an unreadable space is not returned`.
3. **The same person written three ways** ("Aisha", "Aisha Rahman", "aisha rahman"). They must resolve to one entity,
   and a new entity must not be created per spelling. Pinned by Task 4's `resolves spelling variants to one entity`.
4. **Two extraction jobs creating the same entity at once.** There must be no duplicate entity rows. Pinned by Task 1's
   unique index and Task 4's `concurrent extraction of the same name creates one entity`.
5. **The model returns junk** (prose, wrong enum, a missing field). Retry once, then fail with `router_unavailable`; the
   job retries and nothing is half-written. Pinned by Task 2's `invalid JSON twice throws router_unavailable`, and by
   Task 4's `a model failure leaves the previous mentions untouched`.

  ```ts
  export type EdgeType = 'owns'|'uses'|'part_of'|'depends_on'|'member_of'|'related_to';
  export interface ExtractedEntity { name: string; kind: EntityKind; aliases: string[] }
  export interface ExtractedEdge { from: string; to: string; type: EdgeType } // names as in `entities`
  export interface PlacementModel {
    readonly model: string;
    summarizePage(input: { title: string; outline: string[]; markdown: string }): Promise<{ summary: string }>;
    extractEntities(input: { title: string; headingPath: string[]; text: string }):
      Promise<{ entities: ExtractedEntity[]; edges: ExtractedEdge[] }>;
    sameEntity(input: { a: ExtractedEntity; b: ExtractedEntity; context: string }): Promise<{ same: boolean }>;
  }
  export class DeterministicPlacementModel implements PlacementModel { readonly model = 'deterministic-placement-v1'; … }
  export class OpenAIPlacementModel implements PlacementModel { constructor(opts: ChatJsonOptions) … }
  export function createPlacementModel(config: Pick<Config, 'ROUTER_PROVIDER'|'ROUTER_BASE_URL'|'ROUTER_API_KEY'|'ROUTER_MODEL'|'ROUTER_TIMEOUT_MS'|'ROUTER_MAX_TOKENS'>): PlacementModel;
  ```

- Zod limits: `summary` 1–800 characters; at most 40 entities and 60 edges per call; names 1–120 characters; at most 5 aliases. `markdown` is cut to the first 12 000 characters before sending.
- Each OpenAI prompt says the input is untrusted data, not instructions (rule 13).
- Deterministic rules, so tests are predictable:
  - `summarizePage`: the first two sentences of the markdown, or the title when the page is empty.
  - `extractEntities`: every run of 1–3 Capitalised words (`/\b[A-Z][a-z]+(?: [A-Z][a-z]+){0,2}\b/g`) is an entity of kind `other`, except the first word of a sentence when it is in `{The, A, An, We, It, This, That}`.
    Each sentence matching `^(.+?) (owns|uses|depends on|is part of|is a member of) (.+?)\.?$` yields an edge whose type follows the verb.
  - `sameEntity`: true when the normalised names are equal, or when one name's tokens are a prefix of the other's ("aisha" vs "aisha rahman").

### Task 4: Entity extraction and resolution

**Files:**
- Create: `packages/core/src/placement/entities.ts`
- Modify: `packages/core/src/index.ts`
- Test: `packages/core/test/entities.test.ts`

**Interfaces:**
- Consumes: Tasks 1 and 2; the `chunks` of the version (pages and files alike).
- Produces:
  ```ts
  export type ExtractEntitiesResult =
    | { outcome: 'extracted'; entities: number; edges: number }
    | { outcome: 'skipped'; reason: 'not_indexed' | 'inbox' | 'archived' };
  export async function extractVersionEntities(
    params: { tenantId: string; versionId: string },
    model: PlacementModel, embedder: EmbeddingProvider
  ): Promise<ExtractEntitiesResult>;
  /** Thresholds; settings tuned later by the evaluation set. */
  export const ENTITY_MATCH = { trigram: 0.6, maxCosineDistance: 0.15 } as const;
  ```
- Phases:
  - **A (short transactions):**
    - Skip unless the version is the document's indexed one, the document isn't archived, and its space isn't the Inbox.
    - Load the version's chunks (`id`, `text`, `heading_path`, `block_ids`, `content_hash`).
    - Read `entity_extraction_cache` hits for `(model.model, content_hash)`.
  - **B (no transaction):**
    - Call `extractEntities` for each cache miss.
    - Collect the distinct extracted names. Look up candidates for each in a short read transaction: an exact `normalized_name` match or an alias match first, otherwise the top 3 by `similarity(normalized_name, $1) >= ENTITY_MATCH.trigram`.
    - Embed the names with no candidate, plus the names whose only candidates are trigram matches.
    - Call `sameEntity` for each trigram candidate within `maxCosineDistance` of the name's embedding.
  - **C (under `lockDocument`):**
    - Re-check the version is still indexed. Write the new cache rows.
    - Resolve each name to an entity id. Insert unresolved names with `ON CONFLICT (tenant_id, kind, normalized_name) DO UPDATE SET name = entities.name RETURNING id`, so two jobs racing on the same name get one row.
    - Append a new spelling to `aliases` when a name joined an existing entity.
    - Delete this document's mentions and edges, then insert the new ones with the document's `space_id`.
    - Delete entities that had mentions from this document and now have none.
    - For a `person` entity, set `user_id` when exactly one tenant member has a matching name or email local part.

  ```ts
  export interface PlacementFilter { tenantId: string; spaceIds: string[] }
  export interface CardHit { documentId: string; spaceId: string; distance: number }
  export async function searchPageCards(tx: DbTransaction, f: PlacementFilter, vector: number[], limit = 20): Promise<CardHit[]>;
  export interface EntityHit { entityId: string; name: string; kind: EntityKind; match: 'exact' | 'alias' | 'trigram'; score: number }
  /** Only entities with at least one mention in f.spaceIds. */
  export async function findEntities(tx: DbTransaction, f: PlacementFilter, name: string, limit = 5): Promise<EntityHit[]>;
  export interface GraphPageHit { documentId: string; spaceId: string; hops: 0 | 1 | 2; viaEntityIds: string[] }
  /** Pages (kind = 'page') mentioning the seeds (hops 0) or entities reached through edges in f.spaceIds (hops 1–2). */
  ```
